# 🍳 مقادير — Maqader

**نظام مطاعم متكامل: من الوصفة للربح.**
نقطة بيع كاملة + تجهيز داخل المطبخ لكل قسم + وصفات وتكلفة + مخزون وجرد + حسابات وربحية.
عربي أولًا (RTL)، واجهة Neo-brutalist، وضع نهاري وليلي.

```bash
npm install
npm run dev     # http://localhost:5180
```

**الدخول:** أي بطاقة مستخدم على شاشة الدخول (الرقم السري ظاهر عليها).
`1111` = المالك (كل الشاشات) · `5555` = كاشير · `3333` = شيف · `4444` = محاسب.

## الموديولات

### 🧾 نقطة البيع
شاشة كاشير بملء الشاشة (`/pos`): تصنيفات وبحث، إضافات وخيارات لكل طبق مع أثرها الفوري
على السعر **والتكلفة**، صالة/تيك أواي/دليفري، خريطة طاولات، خصومات بأسباب وسقوف،
دفع مقسوم على أكثر من طريقة، باقي النقدية، وفاتورة قابلة للطباعة.
الكاشير شايف **ربح التذكرة ونسبة تكلفة الطعام لحظيًا**.

### 👨‍🍳 شاشة المطبخ (KDS)
`/kds` — التذاكر موزّعة على أقسام التجهيز (مشاوي، أفران، بارد، تحمير، حلويات، مشروبات).
كل تذكرة بتعرض سطور القسم بس، وخطوات تجهيزها من الوصفة، مع عدّاد زمن وتلوين
حسب الزمن المستهدف للقسم، وأزرار ابدأ/جاهز/استرجاع.

### 📖 الوصفات — قلب السيستم
- **دليل الوصفات** — أطباق القائمة ووصفات التجهيز (نصف مصنعة)
- **بطاقة التكلفة** لكل وصفة: مكوّنات قابلة للتعديل مباشرة، شجرة الوصفة بكل مستوياتها،
  المواد الخام بعد النشر، تفصيل التكلفة، و"مستخدمة في" للأثر العكسي
- **التعشيش لأي عمق**: بيتزا ← عجينة + صوص طماطم ← ثوم مجهز. تغيير سعر الثوم
  بيعيد حساب تكلفة البيتزا فورًا
- **الفقد على مستويين**: فقد التنظيف لكل مادة (`trimPct`) وفقد التشغيل لكل دفعة (`batchLossPct`)
- **بطاقات التكلفة** (`/recipes/costing`) + **محاكي**: ارفع سعر مجموعة أو مادة بنسبة
  وشوف أثرها على تكلفة الفترة وأي أطباق هتكسر نسبتها المستهدفة
- **هندسة القائمة** (`/recipes/engineering`): نجوم/أحصنة/ألغاز/كلاب على محورَي
  الشعبية والهامش، مع التوصية لكل ربع
- **خطة التجهيز** (`/recipes/production`): الدفعات المطلوبة اليوم لكل قسم، محسوبة من
  طلب آخر 7 أيام الفعلي

### 📦 المخزون
أرصدة وأيام تغطية وكمية مقترحة للطلب · المواد الخام بتكلفتها الفعلية بعد الفقد ·
فواتير مشتريات (مع تعبئة تلقائية من حد الطلب) · جرد بورقة عدّ وفروق تُرحّل تلقائيًا ·
سجل هدر بأسباب وتحليل · **النظري مقابل الفعلي**: الاستهلاك المتوقع من الوصفات مقابل
اللي خرج فعلًا من المخزن.

### 📊 الحسابات
- **قائمة الدخل** مبنية من دفتر اليومية مباشرة، مع نسبة كل بند من الإيراد،
  هامش المساهمة، ونقطة التعادل
- **الربحية** على أربعة مستويات: الطبق، التصنيف، الفرع، ونوع الأوردر
- **دفتر اليومية** بقيود مزدوجة متوازنة لكل حركة (بيع، تكلفة، عمولات، مشتريات، هدر،
  فروق جرد، مصروفات) + ميزان المراجعة
- **المصروفات** ثابتة ومتغيرة · **ورديات الكاشير** بمطابقة الخزينة

### 🛟 الدعم الفني
`/support` — خدمة دعم كاملة جوه النظام:
- **تذاكر بمستوى خدمة (SLA)** — أربع أولويات من «توقف تشغيل» (أول رد 15 دقيقة) لـ «منخفضة»،
  وعدّاد حيّ لكل تذكرة **بيتوقف وقت ما التذكرة مستنية ردك** فما نحاسبش الدعم على وقت مش في يده
- **خيط محادثة** مع فريق الدعم، إعادة فتح التذكرة، وتقييم الخدمة بعد الحل
- **قاعدة معرفة** (`/support/kb`) بحلول مكتوبة خطوة بخطوة لأشهر المشاكل، بحث بيتعامل مع
  اختلاف الهمزة والتاء المربوطة، وكل مقال بيفتح شاشة النظام المعنية مباشرة
- **تقليل التذاكر**: أول ما تكتب موضوع التذكرة النظام يقترح عليك الحلول الجاهزة المشابهة
- **فحص النظام** (`/support/health`) — نفس روح `npm run verify` بس جوه الشاشة: توازن الدفتر،
  أرصدة سالبة، وصفات تكلفتها بتضرب، أوردرات متعلّقة، نسبة الهدر، آخر جرد… بدرجة صحة واحدة
- **لقطة تشخيص** بتتبعت مع التذكرة (الإصدار، الفرع، الأعداد، سلامة البيانات) فالدعم بيبدأ
  من معلومة مش من سؤال
- مؤشرات الخدمة: متوسط أول رد، متوسط زمن الحل، الالتزام بالـ SLA، ورضا العميل، واستهلاك الباقة

### 🍳 لوحة التحكم
مؤشرات المبيعات والتكلفة والربح بمقارنة بالفترة السابقة، حركة يومية، توزيع التصنيفات،
ذروة الساعات، مقارنة الفروع، أعلى الأطباق، و**تنبيهات تحتاج تصرف** (مواد تحت حد الطلب،
صلاحيات قاربت، فروق استهلاك، هدر فوق الحد) كل واحد بيودّي لشاشته.

## البيانات

مفيش backend. السيستم بيولّد **30 يوم تشغيل حقيقي** عند كل تحميل بشكل حتمي:
~2800 أوردر، ~7400 قيد يومية، مشتريات تغطّي الاستهلاك، أرصدة مخزون، جلسات جرد،
حركات هدر، 90 وردية، وأوردرات مفتوحة على شاشة المطبخ.

أي حركة تعملها إنت (بيع، هدر، شراء، جرد، مصروف) **بتتسجّل فعلًا**: تخصم المخزون،
تقيّد اليومية، وتظهر في قائمة الدخل والربحية. وبتُحفظ محليًا فوق البيانات التجريبية —
و`الإعدادات → البيانات` بيرجّع كل حاجة.

## الاختبارات

```bash
npm run verify   # 131 فحص: المحرك، الوحدات، القيود، منطقية الأرقام، العمليات الكتابية، الدعم والـ SLA
npm run smoke    # رسم 29 شاشة SSR لكشف أخطاء التشغيل
npm run check    # الاتنين
```

`verify` بيتحقق من حاجات زي: تكلفة الوصفة = تكلفة موادها المنشورة، كاشف المرجع الدائري،
خطأ خلط الوحدات، كل قيد متوازن، ميزان المراجعة متوازن، نسبة تكلفة الطعام وصافي الربح
في مدى واقعي، ومافيش رصيد مخزون سالب بعد أي حركة، وعدّاد الـ SLA بيستبعد وقت انتظار العميل،
وملفات الترجمة متطابقة المفاتيح.
